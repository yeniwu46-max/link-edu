# 教学训练页升级说明

> 阶段记录：后续已将机器人替换为无框 Olivia 数字人并加入独立问答和导览。当前行为与最新测量见 [2026-10-08 技术更新](技术更新-沉浸课堂与数字人助手-20261008.md)，下文保留本阶段的实现与验收数据。

## 改动

- 教学训练页保留原深色、紫橙玻璃质感和动态背景，将授课画面放到首屏主位。课题、课堂状态和倒计时留在主画面上方；训练目标、学生设定、时长、授权、录像选择及隐私说明收进默认关闭的“课前准备”。语音评课、摄像头及本机录像选项默认未勾选。
- 桌面授课舞台使用约三分之二的首屏高度，下面紧接播放控制与三个学生席位。手机布局将控制栏换行，详情按需展开。课堂摄像头、录音授权、会话和报告逻辑仍由原有服务处理；学生舞台使用稳定的 `student.id` 键，不因课堂状态查询而重建。
- LINK 小助手更换为紫橙机器人 SVG，提供随课堂状态变化的提示、课前准备、设备检查、点名、字幕和课堂记录快捷入口、FAQ 搜索及训练日志问题记录。提交失败会显示原因并保留草稿；拖动有阈值、点击抑制、视口限位、缩放归位和 Escape 关闭。

## 3D 学生

使用 Kenney Mini Characters 1.0 的 CC0 模型，按“小明（character-male-a，紫色）/小雨（character-female-b，橙色）/小林（character-male-e，蓝色，眼镜）”映射。原 GLB 动画保留 `static`、`idle`、`emote-yes`；运行时调暗并着色材质、叠加边缘光、扫描线、舞台光圈和投影。举手、思考、真实音频播放状态及音量会映射到对应骨骼、光效和字幕标签。

GLB 和眼镜附件合计 397,640 字节；另附贴图、完整 CC0 许可及来源记录。固定上游 ZIP SHA-256、作者、原始/裁剪后模型哈希和改编摘要见 `frontend/public/assets/models/students/credits.json`；官方来源为 [Kenney Mini Characters](https://kenney.nl/assets/mini-characters)。重新准备资产可运行 `python scripts/prepare_student_models.py`。模型在本地提供，运行时不访问 Kenney。

新增 `StudentStage3D` 使用单个 Three.js WebGL renderer 和三个独立视口；学生姓名、回复和点击点名继续使用 HTML，录像从同一帧缓存合成，不新增 WebGL renderer。模型首帧前显示已有图片；单个模型失败时独立回退图片，WebGL 不可用或所有模型失败时整组回退。视口尺寸变化、回复气泡伸缩、页面隐藏和课堂组件卸载都有对应的布局更新或资源清理。

## 验收

- `frontend` 下 `npm test`：159 项通过。
- `frontend` 下 `npm run build`：通过；Three.js 仍产生 588.84 kB 原始 / 147.89 kB gzip 的独立 chunk，构建器给出超过 500 kB 的 chunk 提示。课堂 3D engine 按可视区域异步加载（7.64 kB 原始 / 3.61 kB gzip）。
- 浏览器检查 1280×720：授课舞台边界为 y=113–677，三个学生席位 y=527–677，全在首屏内。768×1024 平板下页面没有横向溢出；375×812 手机下主画面与三个学生顺序正确，学生席位末端仅比首屏下沿多约 9px，向下轻滚可见席位状态文字。
- 三个 GLB 与眼镜均在浏览器正常加载。举手状态可以通过学生按钮读屏及视觉高光确认。缺失模型和模拟 WebGL 不可用时，3 名学生都显示原图；上下文丢失后 renderer 销毁并回退。重复挂载的上下文计数最终回到一个活跃 renderer。减少动态效果保留静态举手反馈，并停止人物扫描、呼吸和视差。
- 机器人助手在小屏显示为可关闭底部面板；点名 FAQ 搜索、Escape 关闭与焦点返回、课前准备快捷入口、问题保存 503 错误提示/草稿保留，以及拖动至视口边缘和视口缩放后的边界修正均已检查。Codex 内置浏览器没有启用原生全屏 API，检查覆盖了课堂的 CSS 全屏回退模式；原生全屏 API 环境仍需现场确认。
- 本机合成录像（不启用摄像头、麦克风或后端）：10.01 秒，1.74 MB，含一个音轨和 244 次学生帧缓存；独立暂停/恢复验收为 8 秒、2 个录像片段、一个音轨。回放画面可见师生画面合成、字幕及三个学生图像。

## 性能测量范围

在 1280×720 浏览器验收页执行 10 秒合成录像时，浏览器 `requestAnimationFrame` 实测均值为 22.6 fps；学生渲染器在采样窗口为 16.2 fps，renderer 每帧 CPU 耗时均值 1.03 ms，模型到首帧记录值为 671.5 ms。三项验收不等价：录像合成由独立 24 fps capture stream 驱动，学生动画有自己的 30 fps 上限，浏览器 RAF 还包含合成视频和页面布局。

这次实测未达到计划的学生渲染 30 fps 桌面目标，因此不报告该目标已达成。该数值来自 Codex 内置浏览器与合成媒体夹具，不代表用户机器的最终前台表现；需要在目标机器前台、正常窗口可见时，以真实教室长时间录制再复测。真实摄像头和麦克风流程没有在这次自动验收中触发浏览器设备权限。
