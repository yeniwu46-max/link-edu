# 临客 LINK 智能课堂升级实施规划（2026-10-04）

## 1. 目标与分工

本轮把“模拟授课 → 课堂证据 → AI 评课 → 针对性复练 → 再次核验”做成完整闭环。优先级 1、2、3 由本工作分支负责实现和验收；优先级 4、5 分配给队友，在其独立分支开发，后续通过明确的数据契约合并。本文是实施计划，以下验收项只有实际代码、测试和人工复核通过后才标记完成。

| 优先级 | 责任 | 交付能力 | 本轮边界 |
| --- | --- | --- | --- |
| 1 | 本工作分支 | 根据教学证据变化的虚拟学生 | 先以“三年级《分数的初步认识》”建立可复现样板，再扩展情境；模拟状态不代表真实儿童学习测量 |
| 2 | 本工作分支 | 评课 → 练习任务 → 再练 → 对照证据 | 不把不同证据覆盖的综合分直接相减或宣称因果改善 |
| 3 | 本工作分支 | 对齐语音、学生回应和视觉事件的教学行为片段 | 只识别可观察行为；识别失败要标“未知”，不推断情绪或人格 |
| 4 | 队友分支 | 课标、概念、误解、策略、量规的知识网络和跨资料推理 | 与现有 `backend/rag/` 对接，独立于课堂运行时；输出带版本的引用链 |
| 5 | 队友分支 | 教师标注、情境题库、模型/规则对比和质量看板 | 与现有 `evals/` 对接，读取脱敏/合成数据；不修改生产评分事实 |

## 2. 当前基线与关键缺口

- `backend/services/classroom_runtime.py` 有三名固定学生、课堂事件和流式回应；`classroom_learning.py` 保存理解、概念和误解，更新依靠模型提出的文本状态及最终转写 ID。缺少版本化的概念/误解定义、转换原因和可重放的状态差异。
- `backend/services/classroom_reports.py` 已有六维证据校验，且 RAG 提供教学依据。`frontend/src/components/ClassroomReport.vue` 的“下一步练习”目前是按低分维度展示固定复盘提示，尚未形成有目标、有证据来源和复练结果的任务。
- 课堂事件已有 `at_ms`、转写、学生回复、播放、动作和视觉采样；它们主要在报告中分别展示，没有服务端统一的教学行为片段层。
- `backend/rag/graph_meta.py` 当前只记录文档、章节、标签的轻量元数据；真正的跨文档图检索属于队友优先级 4。现有 `evals/` 是优先级 5 的起点，不能把“新增评测平台”当成本分支已完成内容。

## 3. 共同数据原则

1. **原始事件优先**：派生结果必须保存来源 `event_ids`、时间范围、算法版本；不能改写原始转写或播放事实。
2. **可观察与推断分离**：`observed` 表示直接由事件记录支持，`inferred` 表示模型或规则解释；缺证据用 `unknown`/`null`，不补造分数。
3. **可重算**：情境版本、规则版本和模型版本应随结果保存；相同事件和相同规则版本应产生相同的规则判定。
4. **权限与隐私**：所有读取和写入沿用课堂归属/JWT；本机录像不自动上传，评测素材优先用合成或脱敏记录。
5. **成本门控**：先复用现有模型调用和事件，再考虑新增付费调用；重评、复练与异步任务须幂等并呈现失败状态。

## 4. 优先级 1：可验证的虚拟学生状态

### 4.1 用户体验

教师开课前可看到训练目标和学生起始情况。例如“小雨把分母越大理解为份量越大”。教师作出具体解释后，学生下一轮回答可纠正误解；只说“错了”或“懂了吗”不能使误解自动消失。报告可展示“起始误解 → 教师证据 → 状态变化 → 后续学生回答”的链条。

### 4.2 实现

1. 建立版本化情境定义：`scenario_id`、学段/课题、概念、误解、起始角色状态、可接受的讲解证据、练习目标。首个情境使用现有分数课题；不要在提示词中散落硬编码规则。
2. 将学生状态拆成明确的 `unknown`、`misconception`、`exposed`、`addressed` 概念状态。`addressed` 仅表示模拟情境中已有支持该概念的教学证据，不代表真实掌握。保留现有自由文本 `understanding` 供自然语言生成，但不让它单独充当状态转移证据。
3. 模型继续提出候选更新，服务端依据本轮最终转写、目标概念、事件归属和格式校验批准或拒绝；记录原因、前后状态和证据 ID。等待、失败、打断的学生回复不能被当作已完成交流。
4. 把获批转移写入不可变 `student_state_transition` 课堂事件，并使重连能从保存状态恢复。针对同一情境、同一组事件可离线重放规则层。
5. 前端提供面向教师的状态变化说明，明确“模拟学生的情境状态”，不称为真实学习效果。

### 4.3 验收

- 有效解释可以改变对应误解；无效口头确认、无关课题、错误引用、未最终确认的转写不能改变状态。
- 三名学生状态隔离；小林的“仅点名回应”规则继续有效；中断和续答不重复计入学习证据。
- 重连后状态、事件链和下一轮回答一致；旧课堂状态能安全读取。
- 自动用例覆盖正反例、边界和重放；真人教师检查自然度和错误纠正是否合乎学科内容。

## 5. 优先级 2：从评课到复练的闭环

### 5.1 用户体验

报告完成后生成 1–3 个可操作的练习候选，例如“提出一个要求解释平均分的追问，等待学生回答后进行反馈”。每个任务显示关联的报告维度、原始证据、目标行为和完成判据。教师可选定任务启动下一节；新报告给出是否观察到目标行为、证据位置以及不可比较的原因。

### 5.2 实现

1. 建立 `PracticePlan` 持久化模型，用 `retest_session_id` 表示一次复练关联，至少包含 `source_session_id`、`source_report_version`、`dimension`、`target_kind`、`source_event_ids`、`criteria`、`status`、`retest_session_id`。
2. 从已经通过证据校验的报告维度与优先级 3 的行为片段选择任务；证据不足时提供不带个体诊断结论的通用练习。保存生成依据和规则版本，避免打开页面就重复生成。
3. 增加有归属校验的任务读取、选择/开始、关联复练、查看对照接口；不让客户端提交任意人的课堂 ID。
4. 报告页提供任务卡与开始复练入口；成长档案显示任务进度、两次课堂的目标行为证据，而非仅显示综合分变化。
5. 只比较同一目标、相同规则口径且证据可用的行为指标；不满足条件时写明“无法判断”，不显示虚假的进步百分比。

### 5.3 验收

- 报告可形成可保存、可恢复、可完成的练习任务；同一报告版本重复访问不会生成重复任务。
- 复练完成后能跳转前后两节的具体证据；未观察到目标行为时保留“未观察到”，而不是判定退步。
- 不同用户不能读写彼此任务；失败、旧报告、重评版本、课堂中断均有明确状态。
- 端到端覆盖“报告 → 选任务 → 授课 → 对照”；人工验收任务建议的教学合理性。

## 6. 优先级 3：教学行为片段识别

### 6.1 用户体验

在报告时间线上标出“教师提问”“候答”“学生完整回应”“追问”“教师纠错/反馈”“小结”等片段。点开片段可以看到原始转写、播放记录和可用视觉证据。识别结果是复盘线索，不自动等同教学质量或最终评分。

### 6.2 实现

1. 定义 `teaching_behavior` 结构：`kind`、`start_ms`、`end_ms`、`event_ids`、`evidence_quality`、`basis`（规则或模型）、`version`、`limitations`。无有效时间戳的事件不形成片段，并在分析限制中说明缺失，不补造时间。
2. 首期用可解释规则串联最终教师转写、点名/问题意图、学生生成、`playback_completed`、中断和下一段教师转写；计算候答间隔时明确起止事件与时间精度。
3. 视觉信息只对板书可见性、教具或动作等可观察项提供附加证据；视觉缺失不否定文字可支持的提问/反馈行为。板书 OCR/语义对齐需要单独验证准确率后再纳入。
4. 在结束课堂/生成报告时派生片段，供评课、复练任务和 UI 共享；提供规则版本及重算入口。不要让前端各自重新定义行为口径。
5. 用标注样本检查每一类片段的误报和漏报，并展示未知率；在没有教师标注前不宣称“自动测量教学能力”。

### 6.3 验收

- 点名提问 → 等待 → 完整播放 → 追问/反馈能形成同一条可回放证据链。
- 未完整播放、打断、无效转写、无时间戳、只有视觉采样等情况不会被误判为完整互动。
- 提问深度与板书等复杂语义在证据不足时为未知；不存在表情推断情绪或把摄像头朝向当作看学生。
- 同一输入在同一规则版本下稳定；与原六维评分并列展示，不静默改变历史评分。

## 7. 队友任务 4、5 的交接契约

### 7.1 优先级 4：知识网络

队友负责 `backend/rag/` 内的概念、误解、策略、课标条文节点与边，知识版本/出处，以及跨文档检索。建议向本分支提供只读接口：输入 `scenario_id`、`concept_ids`、`behavior_kinds`，返回 `claim`、`source_ids`、`path`、`version`、`status`。无命中返回空证据，不改变课堂事实或学生状态。资料授权与过期治理复用现有 RAG 机制。

### 7.2 优先级 5：评测平台

队友负责 `evals/` 中的情境样本、教师标注规范、双人复核、质量指标与比较报告。至少评估学生状态转移、教学行为识别、练习任务适切性、引用正确性、时延/费用。生产 API 只提供经授权的脱敏导出或合成 fixture；评测分数不回写正式课堂报告。

### 7.3 合并规则

- 本分支维护课堂事件、学生状态、复练计划与行为片段的 schema；队友以新增适配层消费，若需改 schema 先在文档中提出版本变更。
- 两个队友模块都应有 `version`、`source_ids`、失败/无依据状态。上线前合并回归覆盖课堂主路径、RAG、前端构建和离线评测。
- 队友分支传来后逐项审查权限、数据库迁移、成本门控与语料许可；不能仅凭合并无冲突视为功能完成。

## 8. 实施顺序与交付门槛

| 阶段 | 主要工作 | 可核验交付 |
| --- | --- | --- |
| A | 固定事件契约；实现优先级 3 的规则片段与反例 | 行为片段 API/报告字段、回放链接、单元与合成课堂测试 |
| B | 建立优先级 1 情境定义、状态转移和课堂恢复 | 分数情境、转移事件、有效/无效讲解测试、真人情境复核记录 |
| C | 用 A/B 的证据接通优先级 2 任务持久化、前端与复练对照 | 报告到复练的端到端流程、权限测试、不可比较场景说明 |
| D | 集成与验收 | 后端/前端回归、构建、离线规则、目标浏览器真机检查、文档更新 |

最终验收以实际代码与数据为准：三个优先级均可在同一情境中连续演示；每个判断都能回到事件，缺证据时明确留空；历史课堂与既有报告可正常读取。优先级 4、5 留在队友分支，合并后另行验收。

### 9.1 已实现的主路径

| 优先级 | 已接通的入口和结果 | 核心文件 |

服务端契约：`GET /api/classroom/sessions/<sid>` 返回 `behavior_analysis`、`practice_plans`、`active_practice_plan`；`GET /api/classroom/practice-plans` 返回当前用户任务列表；`GET /api/classroom/practice-plans/<id>` 返回单项任务；`POST /api/classroom/sessions/<sid>/practice-plans` 为已完成报告幂等补生成任务；`POST /api/classroom/sessions` 接受可选 `practice_plan_id` 启动复练。所有任务读取和关联均校验课堂归属，任务唯一键为来源课堂、报告版本和目标行为。

对队友 4/5 的稳定输入：`scenario.id/version`、`student_state_transition.event_ids/concept_changes`、`behavior_analysis.version/segments[*].event_ids/evidence_quality`、`PracticePlan.criteria.behavior_version`、`PracticePlan.comparison`。队友可先消费这些字段；如需改生产事件或数据库字段，提交 schema 版本提案并与本分支对齐。本文只完成任务划分和接口交接说明，队友分支的代码与评测结果尚未并入。

### 9.2 已验证与仍需人工验收

- 自动验证覆盖有效/无效状态转移、旧状态兼容、完整播放门控、行为片段反例、任务幂等与归属、复练可比性、重评替换和版本不一致。后端测试、前端测试、构建及合成浏览器流程已通过；实际计数以分支交付时的测试日志为准。
- 合成浏览器流程覆盖报告中行为证据和状态变化、任务入口、移动视口与页面错误。它不替代真实麦克风、摄像头、云端模型、网络中断及教师判断。
- 上线前安排真人教师检查分数误解纠正的自然度、任务建议是否适切，以及少量带标注课堂事件的误报/漏报。真机检查语音活动时间戳、重连、摄像头许可和不同浏览器；记录发现后再决定是否开放更多情境。
- 目前情境仅为三年级分数样板；规则识别的是已记录行为，`post_question_silence` 包含可能的系统延迟；`addressed` 是模拟状态。上述限制必须在产品解释与后续评测中保留。
