# B-05 AI 评课外围链路设计

**状态：** 已获用户确认，待文档复核后进入实施计划

**范围：** 分工表 `B-05`，即“AI 评课外围链路”。

**目标：** 让用户可以稳定地选择和恢复历史评课，提交课堂材料生成真实 DeepSeek 报告，在生成中离开页面后恢复状态，处理材料不足和失败重试，并在报告成功后安全追问；所有真实报告、演示报告、生成状态和登录失效状态都必须清晰可辨。

## 1. 当前状态与问题

项目当前已经具备以下初版能力：

- 后端 `POST /api/training/sessions/<session_id>/ai-review` 可生成并保存 DeepSeek 报告。
- `backend/services/training.py` 已保存 `generating`、`succeeded`、`failed` 状态，并有并发和失败频率限制。
- 前端 `AiReviewView.vue` 已支持按 URL 中的 `feedbackId` / `sessionId` 选择报告、生成中轮询、失败重试和追问。
- 已有真实/演示报告判定、材料不足判定，以及追问不修改评分的测试。

仍需要补齐或统一的部分：

- 历史报告选择缺少稳定、明确的页面入口和状态信息。
- 课堂材料草稿已有底层工具，但未完整接入 AI 评课生成流程。
- 生成中状态没有明确的前端超时边界；服务异常时可能长期停留在生成中。
- 生成失败、超时、登录失效、频率限制和网络故障的反馈需要统一。
- 追问请求需要明确的超时和旧请求隔离语义。
- 真实报告、演示报告、真实但材料不足报告的视觉和行为边界需要固定。

## 2. 方案选择

采用**增量补齐现有链路**，不重写评课模块，也不引入新的任务表或队列。

原因：

1. 当前后端生成和追问接口已经存在，并有较完整的测试覆盖。
2. B-05 的主要风险是状态边界和前后端反馈不一致，而不是缺少基础 API。
3. 增量改动可以保留现有报告 JSON、数据库模型和 URL 结构，降低对工作台、成长档案和课堂模块的回归影响。

本轮不采用独立异步任务系统。生成仍由现有后端请求完成，前端通过状态刷新恢复；如果后续需要跨进程任务、取消任务或生产级队列，再单独设计任务系统。

## 3. 用户流程

### 3.1 进入 AI 评课

1. 页面调用 `GET /api/feedbacks` 获取当前用户的评课列表。
2. 默认选择 URL 指定的 `feedbackId`，其次使用 `sessionId`，没有参数时选择列表第一条。
3. 页面将当前选择同步到 `/ai-review?sessionId=<id>&feedbackId=<id>`。
4. 无记录时显示明确空状态，不伪造演示数据。

### 3.2 生成真实报告

1. 用户在当前训练记录下输入课堂转写或教师备注。
2. 输入按 `sessionId` 保存到本地草稿，刷新页面或离开后可恢复；草稿不上传到其他会话。
3. 点击生成后，按钮进入禁用状态，向后端发送 `transcript_text`、`teacher_notes` 和必要的 `regenerate` 标记。
4. 后端先持久化 `generation_status=generating`，再调用 DeepSeek。
5. 成功后保存真实报告，更新页面当前记录，并清除对应草稿。
6. 失败后保存 `generation_status=failed` 和用户可读错误，保留原有报告或演示结果供查看，并允许重试。

### 3.3 生成中离开和恢复

1. 当前报告状态为 `generating` 时，页面每 4 秒刷新评课列表或当前记录。
2. 页面失去焦点、切换标签页或重新进入时，先读取服务端状态，再决定显示生成中、成功或失败。
3. 前端设置明确的等待上限。超过上限时只显示“生成超时，可重试”，不覆盖服务端仍可能存在的 `generating` 状态。
4. 用户再次进入页面时，以服务端最终状态为准；如果服务端已经成功，页面恢复报告；如果失败，显示失败原因和重试入口。

### 3.4 追问

1. 只有 `source=deepseek` 且 `generation_status=succeeded` 的报告可以追问。
2. 材料不足的真实报告仍可追问“需要补充什么证据”，但不计入评分趋势。
3. 空问题在前端拦截，后端也拒绝空白问题。
4. 普通问题只发送当前报告上下文；包含“最近、近 30 天、历史、进步、趋势、相比、上次、变化”等语义的问题，额外发送后端压缩后的近 30 天趋势摘要。
5. 追问成功只返回答案和范围标记，不写入报告、不改变分数、不新增评课记录。
6. 切换报告或组件卸载时，旧追问响应不得覆盖新报告页面。

## 4. 状态模型

### 4.1 报告来源

| 来源 | 含义 | 可否追问 | 是否计入趋势 |
| --- | --- | --- | --- |
| `demo=true` 或非 DeepSeek | 历史演示 / 规则评分 | 否 | 否 |
| `source=deepseek`, `generation_status=succeeded`, 有效证据 | 真实 AI 报告 | 是 | 是 |
| `source=deepseek`, `generation_status=succeeded`, `insufficient_evidence=true` | 真实报告但证据不足 | 是 | 否 |
| `generation_status=generating` | 生成中 | 否 | 否 |
| `generation_status=failed` | 生成失败，可重试 | 否 | 否 |

### 4.2 前端状态

保留现有 Vue 响应式状态，并明确以下状态转换：

```text
idle -> generating -> succeeded
idle -> generating -> failed
failed -> generating -> succeeded | failed
generating + 页面离开 -> 服务端继续生成，重新进入后恢复
任何状态 + 401 -> 登录失效，清理本地 token，显示返回登录入口
```

生成请求和追问请求分别维护 loading、error 和 request id；二者不能互相清空或覆盖。

## 6. 错误处理

| 场景 | 后端语义 | 前端行为 |
| --- | --- | --- |
| 未登录 / JWT 失效 | 401 | 清理 token，显示“登录状态已失效，请重新登录”，提供返回登录 |
| 找不到训练或反馈 | 404 | 显示记录不存在，不跳到其他报告 |
| 训练未完成 / 报告未成功 | 409 | 禁用追问或生成，并提示下一步动作 |
| 请求频率超限 | 429 | 显示稍后再试，不伪造结果 |
| DeepSeek 配置或 provider 失败 | 502 | 保留已有报告，显示失败和重试入口 |
| 请求超时 | 客户端 timeout 或后端可读错误 | 先刷新服务端状态；仍未知时显示超时，不覆盖服务端状态 |
| 网络断开 | 无 response | 显示网络不可用，不标记报告成功或失败 |
| 空问题 / 非法 JSON | 400 | 前后端都拒绝，显示字段级提示 |

所有错误都不能把失败请求转换成成功报告，也不能清空用户仍可查看的原报告。

## 7. 数据安全与边界

- DeepSeek API key 只存在后端配置，不进入前端代码或浏览器请求体。
- 追问只读取当前用户拥有的反馈；历史摘要不包含其他用户数据。
- 历史追问只发送压缩统计和最多 10 条结构化记录，不发送全部原始报告。
- 课堂材料按现有项目约定保存为当前训练会话草稿；本轮不新增文件上传和长期存储接口。
- 不修改模拟授课核心逻辑，不改变评分权重，不恢复旧演示报告的固定加分逻辑。

## 8. 验收标准

1. 已有训练记录可按历史列表选择，并能通过 URL 刷新恢复同一报告。
2. 生成中离开页面后重新进入，服务端成功或失败状态可恢复；不会永久显示生成中。
3. 失败可重试；重试期间按钮不可重复提交；失败不会伪造成功。
4. 材料不足报告显示明确原因，不计入趋势，但仍可追问如何补充证据。
5. 追问成功和失败都有独立反馈；追问不改变报告、评分或历史记录。
6. 普通追问不加载历史摘要，趋势类问题只加载近 30 天压缩摘要。
7. 401、404、409、429、502、超时和网络断开均有可操作提示。
8. 演示、真实、证据不足、生成中和失败状态在页面上可区分。
9. 合成浏览器验收通过，后端测试、前端测试和前端构建通过。

## 9. 明确不做

- 不实现短信或邮箱找回密码。
- 不接入 Google、Apple、Facebook 等第三方登录。
- 不实现文件上传、持久化音视频或转写存储。
- 不新增后台任务队列、取消生成接口或生产部署监控。
- 不修改模拟授课课堂内部逻辑。
