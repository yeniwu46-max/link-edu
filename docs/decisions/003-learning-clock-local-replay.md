# ADR-003：课堂有效时间、模拟学习状态与本机复盘

## 状态与日期

2026-09-13，已采用。增量扩展 ADR-001；不更换在线模型供应商、不增加视频上传接口或业务表。

## 背景

旧课堂将墙钟时间当授课时长，学生文本生成和实际交流容易混淆；视觉不足阻止整份报告，且真实课堂缺少录像复盘。需要保留三个学生、播放器和既有报告，并控制隐私与费用。

## 决策

1. 在既有事件表保存暂停、恢复和报告阶段。原 `at_ms` 继续表示自开课起的墙钟坐标，另计算有效授课时间；不重新编号历史证据。未包含暂停事件的旧课堂仍按原时间计算。
2. 学生 JSON 升级为版本 2。一次流式生成同时返回意图和模拟认知补丁；身份、字段和转写引用由服务端校验。理解变化不等于学习效果测量，回答只有收到有效完整播放回执才算完成。
3. 动作覆盖是证据可用性，不是质量。规则版本升级为 `classroom-readiness-2`、`motion-rubric-2`；视觉不足只拒评教态维度，不自动重写旧报告。
4. 本机录像使用 Canvas + Web Audio + MediaRecorder，保存到独立 IndexedDB。选择它而不是屏幕共享/服务器录制，是为了只合成授权的课堂画面，避免录入设置窗口、桌面内容或上传视频。
5. 录像开始前等待实际音轨就绪，再开启视频时间轴；保存分段墙钟映射，暂停、重连、延迟开录和容量停止形成显式空档。不用简单的“事件时间减去开课时间”跳转。
6. 重复结束请求不重新购买失败的 AI 评课；重新评课必须走明确的人工重试入口。读取状态失败不能触发生成。

## 代价与边界

- 保留单进程课堂服务和现有预算控制；进程突然终止不等价于正常断线处理，部署重启前须结束或暂停课堂。
- 浏览器存储按站点、用户和课堂隔离，是应用级隔离，不是加密保险箱；同一浏览器配置文件的操作者仍可能通过开发工具访问站点数据。
- 编码与摄像头支持依赖浏览器；录制失败不结束课堂。预览前数据只在内存，无刷新/崩溃恢复承诺。
- 模型判断“有效解释”仍需人工抽查，不能把规则校验通过宣称为语义效果已验证。
