# GraphRAG 本机知识库验收 · 2026-10-08

结论：**功能回归通过，检索质量未达标，维持 `RAG_GRAPH_ENABLED=false`。** 本轮未降低相关性门槛、修改标准答案或把未命中的问题从分母中删除。

## 验收环境与数据

- 最初实际配置为 SQLite，知识库文档、切片均为 0；本机 3306 的 MySQL 无法用仓库默认凭据登录。用户明确选择新建独立本机 MySQL 验收库。
- 独立 MySQL 9.3：`127.0.0.1:3307/link_graphrag_acceptance`；导入仓库 manifest 的全部 P0 资料，共 7 份文档、7 个切片，均 ready、启用，无过期文档及向量签名过期文档。
- `local:local-hash-v1:1024`，NumPy 向量索引；混合检索开、精排关、规则查询扩展开；`min_score=0.12`、`fetch_k=20`、`top_k=5`。这是本地词法向量验收，不代表语义 Embedding 的效果。
- 图索引含 25 个节点（含文档、章节等结构节点）及 8 条可检索关系；图谱按请求开启，全局仍关闭。
- 本机验收前端 `http://127.0.0.1:5197/knowledge`，后端 `127.0.0.1:5097`。独立服务使用测试配置隔离现有课堂服务，不改变原开发环境的数据库配置。

## 未达标原因

1. 原黄金集 5 题失败：导入激趣、课堂结构、互动全班回收、教学节奏、表达清晰。现有正文对这些主题覆盖不足；预期文档出现在候选中不代表其足以回答问题。其相似度未通过 0.12 门槛，不能用降低门槛解决缺少依据的问题。
2. 图问题“同一整体的单位分数比较建立在什么教学基础上？”要求标题包含“平均分”、正文包含“平均分的份数越多”，但该句实际位于切片 #3“同一整体与单位分数比较”。它已排第 1、相似度 0.2973；原题标注不一致，仍按原题记失败，并报告数据错误。
3. 图问题“怎样用同大小纸片呈现单位分数依赖的等分基础？”期望切片 #1；它排第 4，但相似度仅 0.0656，未过门槛。图路径不能把该片段单独变成相关证据。
4. 部分标为多跳的问题目前只检查单一目标切片，没有一套已人工审核、必须联合多份依据才能回答的问题集。正式开启前需补齐这一项。
5. 直接问题通过率虽然没有下降，MRR@5 从 0.643 降至 0.479：部分正确结果被图融合挤到更后的位置。下一轮还需检查种子选择、图候选排序与精排，不能只看通过率就开启图检索。

下一轮应先补充有明确来源的教学正文，审核问题与依据切片的对应关系，并建立超过候选预算、能区分一跳与两跳的对照集；再完善词表及关系规则。只有可由现有原文支持的规则可以入图。本轮未用规则替代缺失知识，也未改动原黄金集来制造达标结果。

## 本轮修复与验证

- 修复仅依赖数量/最大更新时间的图缓存签名，同一秒内跨进程更新图 JSON 也能失效。当前通过图谱输入内容指纹实现；会增加每次图检索的数据库读取，后续扩大语料时需要关注。
- 修复过期或未就绪切片仍可通过来源接口打开的问题；现在返回 404。
- 图检索异常会保留原检索结果，并返回明确回退诊断。
- 试检索页增加证据不足提示、逐条相关性标记，按真实边方向显示箭头，原文弹窗展示实际切片 ID；修复按钮对比度和长文本横向溢出。
- 评测补齐 MRR、耗时、完整 JSON 记录及预期来源校验；关闭图检索的基线不受全局开关影响。无答案、零路径和错误来源不会再被忽略。
- 相关后端回归：**44 passed，1 skipped**；其中本轮新增/扩展的图谱与评测检查 **18 passed**。前端构建成功，保留已有的大分块警告。
- 独立 MySQL 集成检查 **21/21 通过**：重建正文/非图元数据/向量摘要不变、图结构稳定、关闭开关结果不变、默认关闭、分类/文档过滤、图开关下的无答案拒答、停用/过期/重新启用/删除、图数据移除/重建、循环与重复路径限制、异常回退。
- 真实页面验证普通、多跳和无答案问题的图开关对照，以及“查看依据 #1”打开切片 #1 的原文。分类与文档范围在 API 层验证；试检索页当前没有对应过滤控件。浏览器未观察到应用错误；入口页有 Three.js 时钟弃用警告。

未调用 LLM 生成有答案的问题；本阶段不对真实模型生成质量作结论。无答案请求实际返回 `insufficient_evidence` 和空引用。
